# HOPE Data Analysis PWA（オフライン対応）

試合記録・能力測定・データ分析のアプリです。一度開けば、電波がなくても使えます。
データはすべて端末のブラウザ内に保存され、外部へ送信されません。

## 中身
| ファイル | 役割 |
|---|---|
| `index.html` | アプリ本体（1ファイル完結。外部の通信なし） |
| `sw.js` | Service Worker。アプリをキャッシュしてオフライン起動を可能にする |
| `manifest.webmanifest` | ホーム画面に追加するための設定 |
| `icons/` | アイコン（192・512・マスカブル512・iOS用180・32） |
| `apple-touch-icon.png` / `favicon.ico` | iPhoneのホーム画面・ブラウザのタブ用アイコン（ルートにも置いています） |

## 公開のしかた（HTTPS で置く必要があります）
Service Worker は **HTTPS のページ**でだけ動きます（開発用の `localhost` は例外）。
フォルダの中身を、そのまま次のいずれかに置いてください。

- **Netlify**: https://app.netlify.com/drop にフォルダごとドラッグ＆ドロップ（無料・アカウントが必要）
- **GitHub Pages**: リポジトリにファイルを置き、Settings → Pages で公開
- **Cloudflare Pages**: フォルダをアップロードして公開

`index.html`、`sw.js`、`manifest.webmanifest`、`apple-touch-icon.png`、`favicon.ico`、`icons/` は**同じ階層**に置きます。
サブフォルダに置いても動きます（パスはすべて相対です）。

## 端末への入れかた
1. 公開したURLを、**電波のある場所で一度開く**（このとき自動でキャッシュされます）。
2. 次のどちらかでホーム画面に追加します。
   - iPhone（Safari）: 共有ボタン → 「ホーム画面に追加」
   - Android（Chrome）: メニュー → 「アプリをインストール」または「ホーム画面に追加」
3. 以降はホーム画面のアイコンから起動でき、機内モードでも使えます。
   チーム画面の「同期とアカウント」にある「オフライン動作」が「有効」になっていれば準備完了です。

## 試合の記録（スタメンと交代）
スタメンでは、打順ごとに選手と守備位置を選び、DH制（指名打者）の有無を選べます。試合中は「交代」から、代打・代走・守備交代・選手交代を記録できます。

## 守備の記録（相手の打球と失策）
相手の攻撃中の「インプレー」で、打球が転がった地点・打球の種類と強さ・処理した守備位置を記録できます。失策は、その守備位置の選手の記録になり、分析の「守備・走塁」で選手別・守備位置別に集計されます。

## 守備中のカウントと牽制
相手の攻撃中も、ボール・ストライク・アウトのカウントが動きます（4ボールで四球、3ストライクで三振）。牽制は、相手の攻撃中は投手の牽制、攻撃中は走者が受けた牽制として記録し、分析の「守備・走塁」で、投手別・走者別に集計します。

## 試合の記録（戻る・進む）
試合の記録の各入力画面に、「◀ 戻る」「進む ▶」があります。戻るは1つ前のプレーを入力した状態で開き、修正して保存し直せます。進むは、戻る前の状態にやり直します。

## 分析 → 失点
分析画面の「失点」から、失点サマリー・失点の場面（場面別・イニング別）・失点パターン（アウト数・失点の形・出塁方法）・最近の推移を見られます。各カードの✦で自動コメント、ⓘで説明を表示します。先攻・後攻での絞り込みもできます。アウトや走者の状態は、このバージョン以降に守備側で記録した試合から集計されます（以前の試合は総失点・イニング別などの一部のみ）。

## 分析の条件（対象・期間・試合の種類・大会）
分析画面の「≡ 条件」をタップすると、条件の画面が開きます。
- **対象**: チーム全体、または選手。
- **期間**: 直近5試合・今月・今年度・シーズン、または「期間指定」（春・夏・秋・前年度のボタン、または開始日と終了日）。前期間との比較は、直前の同じ日数と比べます。
- **試合の種類**: 紅白戦を除く（初期値）・すべての試合・公式戦・練習試合・紅白戦。
- **大会**: 試合に入力した大会名ごとに絞り込めます。大会名は、試合を始めるときの入力欄か、試合の詳細画面（一覧から試合を選ぶ）で入力・変更できます。以前の試合も、詳細画面で大会名を付ければ大会ごとに分析できます。

## 「その他の事象」画面（攻撃・守備）
試合の記録の「その他」を開くと、「打者」と「走者」の2つに分かれたカードが出ます。できない操作は、薄く表示され、理由が書かれます（例: 走者なし、2ストライク・一塁空き（2死）時）。
- **打者**: バントファウル（2ストライクでは三振）、死球、故意四球（申告敬遠）、振り逃げ、打撃妨害、落球（失策）、エンタイトル二塁打、犠打、犠飛、守備妨害（打者アウト）。攻撃では、スクイズも記録できます。守備では、四球・三振・ランダンプレーも押せます。
- **走者**: 盗塁、盗塁死、牽制（セーフ／アウトを選ぶ）、牽制死、牽制エラー、パスボール、暴投、ボーク、失策で進塁、守備妨害（走者アウト）、ボールデッド（+1塁／+2塁）。走者が複数いるときは、走者を選ぶ画面が出ます。
- **振り逃げ**: 2ストライクで一塁が空いているとき、または2アウトのときに押せます。三振をつけた直後なら「直前の三振を変更」になります。原因（暴投・捕逸・失策）を選びます。三振の記録は残り、打者は一塁へ進みます。守備では、暴投・捕逸はバッテリーの記録に、失策は捕手の失策になります。
- **落球（失策）**: 守備では、失策をした守備位置を選びます。ファウルフライの落球なので、打者の打席は続き、ストライクが1つ増えます（2ストライクのときは増えません）。
- **守備での打撃妨害**は、捕手の失策として記録し、その走者の得点は自責点に含めません。申告敬遠は四球に含めます。

## 攻撃の「その他」（申告敬遠・打撃妨害・パスボール・ワイルドピッチ・スクイズ）
自チームの攻撃中の「その他」から、次を記録できます。
- **申告敬遠**: 四球として記録し、四球に含めます（分析の打撃画面に回数を表示）。
- **打撃妨害**: 打者が一塁へ進みます。打席に数え、打数には数えません（出塁率の計算にも入れません）。
- **パスボール・ワイルドピッチ**: 塁上の走者を1つずつ進めます。三塁走者は生還します（打点は付きません）。分析の「得点・走塁」に回数と得点を表示します。
- **スクイズ**: 三塁に走者がいるときに記録します。成功は「犠打」「バント安打」、失敗は「走者が本塁でアウト」「併殺」「三振」「バントがアウト（走者は三塁のまま）」から選びます。成功率は「得点・走塁」に、全体と打者ごとに表示します。スクイズとして記録した打席だけが対象です。

## 分析 → 起用（守備位置・打順）
分析の下部の「起用（守備位置・打順）」で、次を見られます。
- 選手ごとの守備位置（出場試合数と、守備についたイニング数）。
- 守備位置ごとの打撃成績。
- 打順ごとの成績（打席・打率・出塁率・長打率・本塁打・打点など）と、選手ごとの打順の試合数。

このバージョン以降に記録した試合から集計されます。守備のイニング数は、終わったイニングを数えます（試合終了を確定したときの途中のイニングは、アウトや走者などの進行があれば数えます）。

## 守備のインプレー（2つの手順）
相手の攻撃中のインプレーは、①打球の結果・地点・処理した守備位置、②走者の結果と失策、の2つの手順です。失策は、打球を処理した選手とは別の選手（例: 三塁手が処理して一塁へ送球し、一塁手が落球 → 5-3E）にも付けられ、送球・落球・捕球の種類を選べます。1つのプレーに複数の失策も付けられます。

## 守備・投手成績・相手選手
失策の種類（送球・落球・捕球）、パスボール、ワイルドピッチ、ランダンプレー（挟殺）を記録でき、選手ごとに集計されます。相手打者（右打ち・左打ち・両打ち）と相手投手（右投げ・左投げ）を登録すると、対右・対左の成績が出ます。投手の防御率は、自責点×7÷投球回（7回換算）です。試合の画面の上部に、投手・打者・守備のランキングと対戦分析を表示します。

## 選手詳細（4つのタブ）
選手一覧で選手を選ぶと、概要・能力・試合・分析の4つのタブで見られます。測定の入力や登録情報の編集は、右上の「記録・編集」から行います。

## 能力レポート画像
選手詳細の概要タブの「📄 レポート画像を作成」から、打者用・投手用を選んで、2480×3508px の PNG を作れます。画像は端末内で作られ、外部へは送信されません。
保存できないときは、画像を長押しするか、「印刷／PDF」からPDFにしてください。

## 5-10-5の目標タイム
5-10-5（秒）の基準を、目標タイムの表に合わせました。男子の目標は小1→小6で 7.20・6.90・6.60・6.30・6.05・5.90、女子の目標は 7.40・7.10・6.80・6.50・6.25・6.10、上位選手の目標は 6.90・6.60・6.30・6.00・5.80・5.65 です。目標タイムで60点、点数の1段階（10点）は男子の「目標と上位選手の目標の差」（小1〜4は0.30秒、小5・6は0.25秒）で、男子の上位選手の目標は70点になります。女子は同じ1段階を使うので、上位選手の目標は男子より高い点になります。

## アイコンが表示されないとき
- すでにホーム画面に追加してあるときは、いったん削除してから、もう一度追加し直してください（古いアイコンが残ることがあります）。
- Claude の公開ページ（claude.ai のリンク）をホーム画面に追加しても、このアイコンにはなりません。zipを自分のHTTPSのサイトに置いて、そのURLを追加してください。
- ブラウザのタブのアイコンは、読み込み直し（キャッシュの削除）で更新されます。

## 更新のしかた
アプリを変更したら、`sw.js` の先頭近くにある `const VERSION = 'v18';` を `'v20'` のように変えて、
ファイルを置き直してください。端末は、電波のあるときに新しい版を取得し、**次の起動から**切り替わります。

## データについて（重要）
- データは、そのURL（ドメイン）のブラウザ内にだけ保存されます。**URLを変えると、以前のデータは見えなくなります。**
- ブラウザの「サイトデータの削除」や、端末の初期化で消えます。
- 定期的に、チーム画面の「バックアップ（項目ごと）」で書き出して、別の場所へ保存してください。
  項目は、全データ・選手記録・測定記録・試合記録（打席・投球・盗塁を含む）・グラウンド記録・対戦相手記録・シーズン・競技規則セット・チーム設定です。
  各項目の「書き出す」から、コピーまたは「ファイルに保存」ができ、「復元」で、その項目だけを戻せます。
  選手・測定・試合の記録は選手のIDで結びついているため、別々に復元すると対応がずれることがあります。まとめて戻すときは「全データ」を使ってください。
- 複数の端末で同時に使う機能（同期）はありません。

## 動作確認について
パソコン上の Chromium で、「初回読み込み → キャッシュ → 機内モード → 再読み込み・画面移動・データの保持」を確認しています。
iPhone の Safari や Android の実機では確認していません。公開後に、一度、機内モードで開いて確認してください。


## 試合形式（試合の規定）
新規試合の「試合形式」カードで、9回/7回/6回/時間制/その他、規定の回数、タイブレーク（開始の回・無死一二塁/一死満塁/その他）、コールド（回以降・点差を複数登録）、最長の回、時間制限（分）、DH を設定できます。「初期値に戻す」で選択中の規則セットの値に戻ります。
- タイブレーク開始の回に入ると、アウト数・走者を自動配置（自軍は打順の直前の打者から）
- コールド／サヨナラ／規定回数終了／最長の回／時間制限に達すると、記録画面に「試合終了へ／続ける」の提案を表示（自動では終了しません）
- 設定は試合ごとに保存され、試合の規定は試合情報にも表示されます。以前の試合は影響を受けません。


## 打順の提案（分析 → 打順の提案）
試合結果（打席・盗塁）と能力測定から、セイバーメトリクスの考え方で9人の打順を提案します。同じ選手は重複しません。
- 総合力は wOBA（四球・安打・長打の重み付け）。1番＝出塁率＋走力、2番＝最も総合力の高い選手、4番＝残りで長打率最上位、3・5番は総合力順、6〜9番は総合力の高い順。
- 打席が少ない選手は、チーム平均と能力測定値で補正（20〜30打席で実績と半々）。
- 欠席の選手は「出場できる選手」から外すと、残りで再計算します。
- 「確認した」を押した後、試合結果・能力測定の更新で提案が変わると、画面とホームに更新のお知らせを出します。
- スタメン設定画面の「分析の打順提案を反映」で、そのまま打順に入れられます（守備位置は元の選択を引き継ぎます）。

### 打順の提案の方式
画面上部で3方式を切り替えられます（選んだ方式は保存されます）。
- **USA方式**: 1番＝出塁率＋走力、2番＝最も総合力の高い選手、4番＝長打率最上位、3・5番は総合力順。
- **JPN方式**: 1番＝俊足・出塁、2番＝三振が少なく小技ができるつなぎ役、3番＝打率の高い巧打者、4・5番＝長距離打者（長打率・打点）。
- **KOR方式**: 1番＝出塁＋走力、2番＝出塁率が高く三振の少ない選手、3番＝最高の打者、4番＝長打の中軸、5番＝得点圏打率の高い勝負強い打者、9番＝出塁できる「第2の1番」。
JPN方式・KOR方式は、それぞれの野球で一般的とされる傾向を成績に当てはめた目安です（公式なルールではありません）。更新のお知らせは方式ごとに管理します。

## 打撃分析のカード構成（分析 → 打撃）
失点分析と同じく、カードごとに ✦（分析コメント）と ⓘ（見方の説明）を付けました。
- **打球カード**: 地点／方向／種類／引っ張りの4つの見方。地点では「すべて・ヒット・アウト・長打」の絞り込み、点とヒートマップの切り替え、＋／−での拡大縮小ができます。
- **打撃サマリー・打者ごとの判定・打球の強さ・走者状況別・OPSの推移**にもコメントと説明を追加しました。
- 打球の位置は、これから記録する打球は角度と距離で正確に保存します。以前の記録は方向と距離から位置を推定して表示します。
- 引っ張り／流しは、選手の打席（右・左・両）で判定します（両打ちは相手投手の左右で決めます）。

## 投手分析のカード構成（分析 → 投手）
失点・打撃分析と同じく、カードごとに ✦（分析コメント）と ⓘ（見方の説明）を付けました。
- **投球結果**: 「割合」（見逃し・空振り・ファウル・ボール・インプレー・死球のドーナツ図）と「カウント別」（0B〜3B × 0S〜2S の表。ストライク率／空振り率／ボール率／被打率を切り替え、色の濃さで高低を表示）。
- **制球と球の強さ**: 初球ストライク率・空振り率・ボール率を前期との差（pt）つきで表示。1打者あたりの球数も出します。
- **被打球**: 「地点」（点／ヒートマップ、すべて・被安打・アウト・長打の絞り込み、＋／−で拡大縮小）と「内訳」（方向と種類ごとの割合・被打率）。
- カウント別の被打率は、投球の記録順から打席を再現して推定します（打席の記録がない試合は含みません）。


## ホームの打球傾向
- ホームの「打球傾向」を、すべて／右打者／左打者／選手 の切り替え、ゾーン／点（直近40打球）表示、＋／－拡大、凡例の件数、方向の一言まとめに変更。
- ✦で分析コメント、ⓘで見方の説明。「分析 ›」から打撃分析へ移動できます。
- 以前の記録の打球位置は方向と距離からの推定です。


## 得点・走塁／守備・走塁／能力×実戦の ✦ⓘ
- 各カードに ✦（分析コメント）と ⓘ（見方の説明）を追加。
- 得点・走塁は、走者状況（場面別・イニング別、アウト別）、得点パターン（アウト数・得点の形・出塁方法）、バント、得点期待値（送りバント・盗塁・表）に作り直しました。
- 得点率・期待値は、回とアウトを記録した試合から集計します（これから記録する試合が対象。以前の試合は含まれません）。期待値は一般的な値と自チームの記録を混ぜて計算します。


## 早稲田式スコアブック
- 試合の詳細画面の「スコアブック（攻撃・守備）を見る・印刷」から開きます。
- 「攻撃（自チーム）」は打順×イニングのダイヤモンド表、「守備（相手の攻撃）」は相手打者の表です。イニングスコア（R・H・E）と投手成績も付きます。
- 「印刷 / PDF」で印刷、またはPDFとして保存できます（A4横向き）。
- 回・アウトの記録がない以前の打席は、順番から推定します。守備位置や方向がない記録は、種類だけを表示します。
- スコアブックの投手成績に、投手ごとの暴投・ボーク・刺殺・補殺の列を追加。


## 測定記録の一覧出力
- 選手一覧の「測定記録を画像・PDFで出力」から開きます。
- 全選手の14項目と総合を一覧にし、「画像（PNG）」で保存、「PDF / 印刷」で A4 横向きの印刷・PDF保存ができます。

## データ保存の安全性とバックアップ（Phase 1）
- 保存：保存に成功すると画面下に「✓ 保存しました」と出ます。失敗したときは画面上部に赤い警告を出し、成功とは表示しません（容量不足は理由も表示）。保存後に読み戻して内容を確認し、失敗したときは1回だけ再試行します。
- 容量：「チーム」→「保存の状態とバックアップ」で使用量（目安）を確認できます。約85％を超えると黄色い警告が出ます。
- 自動バックアップ：起動時（12時間以上空いたとき）と試合終了後に自動で作成します。この端末のIndexedDBに保存し（容量の大きい端末の保存領域とは別）、自動・手動・復元前など種類ごとに最新5世代を残します。「今すぐバックアップ」で手動作成、一覧から「書き出す」「復元」ができます（復元は2回押し）。
- 復元：実行前に内容を検査（形式・件数・チェックサム）し、問題があれば拒否します。復元の前に必ず現在のデータをバックアップし、失敗したときは元のデータに戻します。以前のバックアップ（旧名称・チェックサムなし）もそのまま読み込めます。
- 破損検知：起動時に保存データが壊れていたら、赤い警告を出し、壊れたデータを退避して上書きを止めます。「バックアップから復元」「壊れたデータを書き出す」「退避して新しく始める」から選べます。「データを診断」でID重複や紐づかない記録も確認できます。
- 操作履歴：保存失敗・バックアップ・復元・取り消しなどを別キー（dl_log）に最新200件記録し、「操作履歴」に表示します。
- 取り消し／やり直し：ほかの試合の記録が増えている・履歴が壊れているときは、データを壊さないよう取り消し・やり直しを止めます。
- 二重登録防止：記録ボタンや「登録」の連打を無視します。
- 既存の保存キー（dl）とデータ形式は変えていません。全削除の前にも自動でバックアップを作ります。


## IndexedDBへの段階移行（Phase 2）
- いまの保存先は従来どおり localStorage の `dl` です（既存機能のデータの読み書きは変えていません）。これに加えて、IndexedDB（`hope_main`）に、照合済みの写しを持ちます。
- 起動時に、IndexedDBがまだ空で、データがあれば自動で移行します。「チーム」→「IndexedDB（段階移行）」から、手動の移行・再照合もできます。
- 移行の流れ：①移行前バックアップ（作れなければ中止）→②移行前データのスナップショットを保存→③IndexedDBへまとめて書き込み（途中で失敗したら全体を取り消し）→④読み戻して、選手・試合・打席・投球・進塁記録・測定などの件数、各IDの一覧、内容のチェックサムを照合→⑤一致したときだけ「移行済み」に確定。一致しないときは元の状態に戻し、localStorageのデータは変えません。
- 移行後は、保存のたびにIndexedDBへ自動で同期（照合つき）します。同期に失敗しても、localStorageのデータは無事です（「同期が遅れています」と表示）。
- 旧データ（`dl`）は削除しません。移行前のスナップショットも別に残します。
- 破損時：`dl` が壊れていたら、赤い警告の「IndexedDBの写しから復元」で戻せます（復元前の自動バックアップつき）。
- 旧形式のJSONバックアップ（旧名称・チェックサムなし）も、これまでどおり読み込めます。復元後はIndexedDBにも同期します。
- バージョン管理：データ形式のバージョン（現在 v1）をIndexedDB内に記録し、古い場合は順にマイグレーションします。データベースの版（現在 v2）が上がるときは、既存のデータを残したまま保存領域を追加します。
- 「整合性チェック」で、IndexedDBの内容・件数・チェックサム・localStorageとの一致、ID重複や紐づかない記録を確認できます。
- IndexedDBが使えない端末でも、これまでどおりlocalStorageで動作します。


## 試合記録の正確性（Phase 3）
- 公式記録と分析用の集計を分けました。
  - 公式記録（投手成績の失点・自責点）：イニングを時系列で再構成して計算します。
  - 分析用（失点の分析・得点パターンなど）：これまでの集計（ur／xr／xu など）をそのまま使います。
- 自責点：失策・打撃妨害・捕逸・振り逃げ（捕逸／失策）で出塁・進塁した走者の得点、失策がなければ3アウトになっていた後の得点は自責点になりません。暴投・ボークは自責点です。タイブレークで置かれた走者の得点も自責点にしません。
- 責任走者：継投のとき、塁上の走者の得点は前の投手の失点・自責点です。野選で走者が入れ替わった場合、打者走者は、アウトになった走者の責任投手を引き継ぎます。
- 得点の判定：打者アウトまたはフォースアウトが3アウト目のとき、同時に走者が本塁に達しても得点にしません（攻撃・守備とも）。
- 打点：振り逃げ（捕逸・暴投・失策）で入った得点は打点にしません。
- 盗塁（守備側）：盗塁成功を記録に残すようにしました（再構成のため）。
- 継続試合：「交代・設定」の「試合を中断する」で、理由（雨・天候／日没／時間切れ／その他）を付けて中断できます。試合一覧には「⏸中断中」と出ます。「この試合の記録を再開」で、中断した時点の状態から続けられます。時間制限の経過時間は、中断した時間を除いて続きます。
- データの形：新しく始めた試合に、順序情報（ts）と走者の移動先（db／dr）を追加で記録します。以前の試合は、これらがないため、従来の計算のままです（数値は変わりません）。
- 整合性チェック：再構成した得点が記録と合わないイニングは、従来の値を使います。試合の失点が記録と合わないときは検出できます。
- 更新するとき：sw.js の `const VERSION = 'v51';` を `'v52'` に変えてください。


## 試合分析の拡張（Phase 4）
既存の分析画面・既存の計算は変えていません。分析画面に「📊 拡張分析（打撃・投手・チーム）」ボタンを追加し、新しい画面で表示します。上部の絞り込み（期間・チーム・試合区分など）は既存の分析と共通です。

### 表示と集計条件
- 各表の見出しに、集計の対象（打席数・被打席数・投球数・試合数）を表示します。画面上部に「集計ID」も表示し、同じ記録・同じ条件なら同じIDと同じ結果になります。
- データ不足：打席20未満（投手の被打席は30未満、投球別は10未満、試合別は5未満）の行には「参考値」と表示します。
- 打撃：右投手/左投手別、右打者/左打者別、カウント別（有利・並行・ストライク先行・追い込まれ）、走者状況別（なし・一塁のみ・得点圏・満塁）、得点圏打率、初球打ち、追い込まれた後、球種別、打球方向（引っ張り/センター/流し）・打球の深さ。
- 投手：投手別被打率、球種別・コース別（投球の記録）、イニング別、先発/中継ぎ/抑え別。
- チーム：得点期待値（24状態）、状況別の得点期待値、RE24（打席ごとの得点価値）、勝利確率の推定、攻撃力・守備力の推移、期間別比較。

### 計算式
- 打率＝安打÷打数、出塁率＝(安打＋四死球)÷(打数＋四死球＋犠飛)、長打率＝塁打÷打数、OPS＝出塁率＋長打率（既存の st() と同じ）。
- 初球打ち率＝初球で打席が終わった数÷打席数。追い込まれた後＝打席の最終カウントがストライク2。
- 得点圏＝二塁または三塁に走者がいる。先発＝その試合の最初の投手、抑え＝勝っている試合の最後の投手（先発以外）、それ以外は中継ぎ。
- RE24（打席）＝（打席後の得点期待値）−（打席前の得点期待値）＋その打席で入った得点。得点期待値は既存の得点期待値表（少ないデータは全体表と混ぜて補正）を使います。
- 勝利確率（参考値）：p＝Φ(E/√v)。E＝得点差＋μ×（自チームと相手の残り攻撃回数の差）＋（攻撃中なら＋μ、守備中なら−μ）、v＝1.8μ×（残り攻撃回数の合計＋0.5）、μ＝チームの1回あたり得点（10回未満は1.0）。簡易モデルで、常に参考値です。
- 球種・コースの記録は新機能です。記録画面の「球種・コース」から選ぶと、その球に印が付きます。以前のデータには球種・コースがないため、その分は「未記録」として扱い、集計に含めません。

## 試合削除の改修

- **不具合の修正**：従来の「試合を削除」ボタンは、同名の別処理（目標の削除）に先に反応して、何も削除されない状態でした。あわせて、盗塁などの関連データが削除対象に入っていませんでした。
- **削除前に関連データを一覧表示**：その試合に結び付く記録（打席・投球・守備・牽制・イベント・攻撃側イベント・盗塁など、`gid` を持つ全データを自動で収集）の件数と、動画（ファイル・タグは削除せず、試合との紐付けだけ外す）を確認画面に表示します。
- **削除前バックアップ**：削除の直前に、関連データを含む完全バックアップ（種別「削除前」）を自動作成します。作成できないときは削除を中止します。保存に失敗したときは元に戻します。
- **復元**：削除した試合は「試合」画面の「🗑 削除した試合」（`S.trash12`）に、関連データごと残ります。ここから復元できます。自動では消えません（完全削除は確認のうえ、実行前にバックアップ）。ファイルへの保存・読み込みもできます。
- **孤立データの自動検出**：試合に結び付かなくなった記録・動画、選手が見つからない打席、紐付け先の無い動画タグを、「試合」画面で自動検出して警告します。**検出だけで、削除・変更は一切しません。** 復旧候補として「削除した試合から復元」または「試合として復元（簡易：日付・相手・得点を確認して作成）」を提示し、「ファイルに保存」「今は表示しない」ができます。
- データ構造：`S.trash12`（削除した試合）、`S.gign12`（表示しない孤立データ）を追加（旧データはそのまま使えます。バックアップに含まれ、クラウド同期の対象外）。
- 制限：簡易復元で作る試合は、打順・スコアの詳細（得点の内訳など）が無い「記録のみ」の試合です。クラウド同期の他端末には、削除した試合の履歴（ごみ箱）は同期されません。

## 選手の成長（Phase 5）
既存の選手画面・測定・能力評価の数値は変えていません。「分析」と「選手詳細」にボタンを追加し、新しい画面「📈 選手の成長」で表示します。新しく保存する項目は、目標（`gl`）とポジション経験履歴（`px`）だけで、測定記録・選手記録の形式は同じです（バックアップの「測定記録」に含まれます）。

### 評価の考え方（身体能力・実戦能力・成長度を分けて表示）
- 身体能力（測定）：各測定値を、測定日時点の学年・性別の目安（平均と標準偏差）と比べて「60＋10×(測定値−平均)÷標準偏差」で点数化（タイムは小さいほど高得点）。60点＝目安の平均。既存の能力評価と同じ式です。学童野球の設定のときのみ算出します。
- 実戦能力（試合の記録）：今年度の試合（紅白戦を除く）から。打撃＝OPS×100（上限100）、投球＝(ストライク率÷70%×100＋空振り率÷20%×100)÷2、守備＝守備率。
- 成長度（推移）：測定ごとの点数（学年補正ずみ）を時間に対して直線で当てはめた1年あたりの変化（傾き）。3回以上かつ半年以上の期間がある項目だけ判定し、+2以上＝上昇、−2以下＝低下。評価できる項目の6割以上が上昇し平均傾きがプラスなら「継続的に成長」、半数以上が低下なら「要観察」。2項目未満は「データ不足」。体の成長による伸びは学年補正で取り除きます。
- 公平性：他の選手との順位づけはしません。未測定の項目は低く扱わず、測定した項目だけを平均します。測定項目が少ない（領域は2項目未満、身体の総合は3項目未満）場合は60点寄りに補正し「参考値」と表示します。実戦は打撃20打席・投球30球・守備10機会に満たないと参考値とし、課題にも使いません。学年・性別の目安と比べるため、学年が違う選手も同じ基準で見られます。

### 画面
- 選手別：成長（成長曲線・継続的な成長の評価・測定項目別グラフ・過去最高値・測定値の比較・成長率）／能力（レーダーチャート・個人別能力評価・走力・下半身・上半身・打撃・投球・守備）／目標（個人目標・達成率）／ポジション（経験履歴）／課題・練習（個人別課題・練習メニュー）／レポート（コピー・印刷）。
- 学年別比較、ポジション別比較・全ポジション経験状況、測定会の一括登録、個人別課題一覧。
- 領域：走力（30m走・一塁到達・二塁到達・ベース1周）、下半身（立ち幅跳び・5-10-5・反復横跳び）、上半身（握力・遠投・ロングティー）、打撃（スイングスピード・ロングティー）、投球（球速・送球正確性）、守備（二塁送球タイム・送球正確性・遠投）。

### 計算式・条件
- 成長率＝(最新−初回)÷初回×100（タイムは短縮を＋）、年換算＝成長率÷期間日数×365（90日以上のみ）。
- 目標達成率＝(現在値−開始値)÷(目標値−開始値)×100（0〜100%）。開始値＝目標を作った時点の最新値。目標値の目安は、現在値から標準偏差の0.3倍良くした値。
- 過去最高値＝全測定のうち最良の値（記録は消えません）。
- 測定会の一括登録：空欄は保存しない。同じ選手・項目・日付の記録は上書きしない。値が0以下、または目安から標準偏差の5倍以上外れていれば、入力ミスの可能性があるため保存せず知らせる。場所・条件は各記録のメモに残り、測定値の比較に表示されます。
- 学年別・ポジション別：測定のある選手だけを平均し、3人未満は参考値。助っ人は含みません。ポジションは登録ポジションで分類（複数登録は各位置に含む）。
- ポジション経験：試合記録（このバージョン以降の試合のイニング記録）＋登録ポジション＋手入力の履歴。
- 課題：領域評価50点未満＝課題、50〜59点＝伸びしろ、推移が下向き・半年以上未測定・位置未設定は確認。練習メニューは課題の領域ごとの例です（回数・強度は指導者が学年に合わせて決めてください）。

- 年間活動報告：練習・出席・試合・大会・遠征・会計・用具・当番を1つの文章にまとめ、コピー・印刷。
- お知らせ：用具不足・返却期限・出欠の未回答（7日以内の予定）・予算超過を、チーム運営画面とホームに表示。

### 戦術支援（すべて参考。最終判断は監督・指導者）
- 選手の出場状況：出場試合・出場率・打席・守備イニング・最後の出場日・守備経験。出場率が中央値の半分未満の選手に⚠（紅白戦は除く）。出席率と未経験ポジションも並べて表示。
- 打順候補の比較：前回のスタメン／分析の提案／手動／並べ替え案（全体・対右・対左）を最大6件、全体・対右投手・対左投手の1試合期待得点で比較。計算：各打者の打席結果（三振・凡打・四球死球・単打・二塁打・三塁打・本塁打）の確率を、本人の記録をチーム平均へ25打席ぶん寄せて求め（左右別は本人の全体へ20打席ぶん寄せる）、アウト・走者・打順の状態（24状態×9人）を正確に計算します。進塁の標準設定：単打で二塁走者は60%生還、一塁走者は25%三塁へ、二塁打で一塁走者は50%生還、凡打で併殺10%・犠飛30%・二塁走者の進塁20%。チーム固有の進塁率・走力・守備は反映していません。差が0.1点未満は実質同じです。並べ替え案は山登り法で、選手の入れ替えはしません。
- 右投手・左投手別：上記の対右・対左の列。相手投手の左右は打席記録（なければ試合の設定）から。
- 守備配置の比較：適性点（0〜100）＝登録ポジション＋その位置の出場試合＋その位置の守備率（機会が少ないほど平均へ）＋身体能力の目安。経験のない位置は35点以下に抑え⚠表示。合計が最大になる配置を計算（動的計画法）。「固定」で位置を動かさずに計算。
- 守備交代候補：前回のスタメンの位置ごとに、控えの上位3人（5点以上高い候補に↑）。
- 代打候補：場面（アウト・走者・投手の左右）を選び、各選手の期待得点（打席結果の確率×チームの期待得点表）を比較。
- 代走候補：控えの走力点・盗塁成績・打撃の差を並べて表示（期待得点では計算していません）。
- 投手交代候補：直近の球数と上限、休養日、今年度の被打率・四球率・三振率・対左右の被打率（対戦15未満は「-」）。
- 期待得点表：チームの試合記録から作った場面別の期待得点（記録が少ない場面は標準値へ寄せ、「参考」表示）。
- 「出欠から考える」：予定を選ぶと、欠席の選手を打順・守備・代打の候補から外します。

### 制限
- 戦術の計算は目安で、実際の勝敗を保証しません。モデルの進塁設定は固定値です。人数・打席が少ない選手は参考値です。

## Phase 11：動画・カメラ映像との連携（任意）

動画機能は**任意**です。動画を使わなくても、これまでの機能はすべてそのまま使えます（分析 → 🎥 動画、またはチーム画面のボタンから）。

### 手動の機能（優先して実装）
- **動画の取り込み**：「ファイルを選ぶ」／「カメラアプリで撮影」（端末の標準カメラ）／「アプリ内で録画」。種類（打撃・投球・守備・その他）・試合・選手を付けて管理。ライブラリで種類・試合・選手で絞り込み。

- **時刻タグ**（打撃・投球・守備・好プレー・課題・基準点・メモ）：位置の微調整（±0.1秒）、メモ、削除。
- **プレーとの紐付け**：タグを、試合記録の打席・投球・守備のどれかに紐付け（選択画面）。紐付けはタグ側にだけ保存され、**試合の公式記録（打席・投球・守備）は変更しません**。「タグ・プレー一覧」で、種類・紐付け有無・試合・選手・プレー結果で絞り込み、試合ごとにプレーと動画を対応表示。
- **クリップ**：A〜B区間を名前付きで保存。再生・ループ・名前変更・削除・書き出し（ブラウザが対応する場合）。
- **ストライクゾーン表示**（位置・大きさ調整、タップでコース記録：9分割＋ゾーン外）と **守備位置オーバーレイ**（位置・大きさ調整、守備位置の強調）。
- **計測ツール**：角度（3点）・傾き（2点）、**姿勢（手動）**：体の11点をタップしてひじ・ひざの角度、体幹・肩・腰の傾きを計算。
- **フォーム比較**：2本（同じ動画でも可）を「左右」「重ね（濃さ調整）」「差分」で表示。同期点でタイミングを合わせ、同時再生・コマ送り・スロー。比較は名前を付けて保存。

### 自動解析（参考情報。公式記録には書き込みません）
- **動きの候補**：映像の変化が大きい瞬間をフレーム差分で探し、タグ候補として表示（「タグにする」で採用）。
- **打球方向の補助分析**：ホームベース→センター方向の基準線を設定し、打球をタップするとテンプレートマッチングで追跡し、基準線に対する角度と、引っ張り／センター方向／逆方向（打者の左右で判定）を表示。
- **リリース位置の補助分析**：リリースの瞬間にタップ、基準点（投手板）と縮尺（長さ既知の2点）を設定するとcm単位でばらつきや基準点からの位置を表示（未設定なら画素単位）。
- **解析まとめ**：選手別に投球コース、紐付けた投球結果との対応、打球方向、リリースのばらつき。

### 保存容量とオフライン
- 動画ファイルは端末のIndexedDB `hope_video11` に保存します（`S` には動画の情報だけ `S.v11`）。保存容量と上限の目安を画面に表示し、容量不足・保存失敗は分かりやすく表示します。
- 取り込み時に「この端末に保存する」を外すと**今回だけ開く**（保存しない）。タグ・クリップは残り、次回は同じ動画を選び直します。「ファイルだけ削除」も可能。
- **動画ファイルはバックアップ・クラウド同期に含まれません**（タグ・クリップ・計測・解析結果は `S.v11` としてバックアップに含まれ、クラウド同期の対象外）。端末を変えるときは動画ファイルを別途コピーしてください。
- 取り込み・再生・タグ・比較・自動解析は**すべて端末内で完結**し、オフラインで使えます。
- カメラが使えないとき（許可なし・未対応・http・他アプリが使用中）は、理由を表示して「カメラアプリで撮影」「ファイルを選ぶ」を案内します。

### データ構造（追加のみ）
- `S.v11 = {v:1, vd:[動画], set:{}, cmp:[保存した比較]}`。動画：`{id,nm,ty,gid,pid,mime,sz,dur,w,h,bad,fps,ca,lm,d,nt,tg:[タグ],cl:[クリップ],ms:[計測],zn,fo,an:{rel,hit,pose,mot,ax,cal,ref},hasFile}`。タグ：`{id,t,k,pid,ref:{k,id},tx,pos}`。`S.v11` が無い旧データ・旧バックアップは、そのまま使えます（開いたときに作成）。

### 制限（正直な記載）
- **姿勢の自動推定は未実装**です（AIモデルをオフラインで同梱できないため）。手動の姿勢計測で代替しています。
- 自動解析は単純な画像処理で、映像の明るさ・画角・ブレで誤差が出ます。あくまで参考情報です。打球の追跡は、10コマ程度の短い区間です。

- 実機のiPhone/Androidのカメラでの録画・容量上限は未確認です（Chromiumの擬似カメラでテスト）。

## Phase 13：試合記録の確認と確定
既存の記録・集計・画面は変えていません。試合の詳細画面（「この試合の記録を再開」の上）に「記録の確認と確定」を追加しました。記録チェックは記録を変更せず、自動で直す・消すこともしません。
- 記録チェック：日付・相手名／打点合計と得点の矛盾／イニング別得点と点数のずれ（記録漏れ・手動補正）／打順・守備位置の重複／名簿にいない選手／アウト数3以上の打席／重複入力の疑い／勝利・敗戦投手の不整合／先発投手の未設定／中断中・終了未確定。結果は「誤り候補（✖）・要確認（⚠）・参考（ℹ）」で表示し、「記録品質：良好／要確認／要修正」を出します。
- 状態：下書き／確認済み／確定。変更は履歴（最新50件）に残ります。誤り候補・要確認があるまま確認済み・確定にするときは、内容を見せて確認します。
- 確認・確定後の変更検出：状態にした時点の得点・勝敗・打席の件数と内容・投球／守備の件数を控えておき、その後に変わったら理由とともに警告します。
- 確定済みの試合：記録の再開・勝敗の変更・大会名の変更の前に確認を出し、続けると「確認済み」に戻して履歴に残します（編集そのものは止めません）。
- 試合終了前のチェック：勝敗・投手の確定時に、確認事項があれば一覧を見せて、続けるか戻るかを選べます。
- 定期診断：試合一覧に「🔎 試合記録を診断する」を追加。7日以上空くと起動後の試合一覧で自動診断し、確認が必要な試合があるときだけ通知します。
